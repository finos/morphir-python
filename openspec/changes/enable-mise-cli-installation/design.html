Context

See proposal.md for motivation. Release already publishes pure CLI wheel/source artifacts to PyPI and GitHub and a separate WASM bundle. It builds qualified native wheels for five platforms. The Python API pins native 0.1.1; the current CLI/core versions are 0.1.0. The existing Build category owns installed package checks. PR 52 implements installer assurance at c174a30; OpenSpec now records that work and the verification still open.

Goals and non-goals

Keep mise installation on the published Python package route and verify exact candidates before promotion. Preserve independent versions, existing native qualifications and the dependency-free core library. Frozen Python executables, MEP process serving and new protocol support belong outside this change; see add-process-mep-extension.

Decisions

INS-1. Use the Python package backend

Provide canonical configurations in examples/install for uv and actual pipx, with managed CPython 3.14, explicit CLI version and wheel-only policy. Keep PyPI as the installation source and GitHub assets as mirrors. A standalone CLI archive would add embedded-runtime maintenance and platform packaging; the maintainer selected the package route.

INS-2. Bootstrap pipx through a portable explicit backend

The first matrix run proved Windows CLI wheel and mise/uv behavior, then failed when mise's short pipx name selected a macOS/Linux-only backend. Bootstrap pipx through the PyPI backend with uv, give the pipx dependency an explicit alias so installation order is enforced, and keep the CLI tool's uvx=false selection. The corrected canonical configuration must pass clean Windows qualification; do not drop Windows or replace its actual pipx check with uv.

REL-1. Keep qualification with its existing producers

Use scripts/qualify_mise.py from the Build category and the existing release matrix. Candidate identity validators run before dependency lookup. Download dependencies under the release constraints once, verify supplied wheel bytes, then install from that offline wheelhouse in separate temporary mise environments. Retain package versions and hashes. Exercise both IR formats and generated semantics without Rust on the execution PATH.

Ordinary PR/main CI owns Linux checks. Manual/native qualification extends the existing five-platform matrix. CLI tags consume already published native wheels and require the matrix before PyPI and GitHub publication. Reuse compatible Linux producer evidence. No new schedule or publication privilege is needed.

REL-2. Seal the final WASM asset names

Validate the actual .sha256 contents, not only their syntax. Keep source/version/descriptor checks, then compute SHA256SUMS after staging the versioned descriptor name and reports. The existing publisher rechecks that receipt immediately before uploading. A generic checksum implementation provides the byte check; it is not reimplemented in the application.
