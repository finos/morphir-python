Context

See proposal.md for the motivation. The draft codec (morphir.ir.v4.codec) follows the finos/morphir v4 schema at FINOS_MORPHIR_PIN = "efa36060", which is still finos/morphir main on 2026-10-27. It writes and reads only the expanded spelling ({"Kind": {members}}); compact spellings are the later re-sync in morphir-ukvn.8.16.

The sources for the new shapes, in order of authority:

The in-memory v3 to v4 to v3 round trip is a requirement (ir/migrate, "Shared subset round trips"), and the morphir-elm reference model has 10 inputs (8 module-level, 2 let-bound) whose resolved type differs from the declared type (alias expansion and type-variable instances, for example float-alias resolved to Float).

Goals and non-goals

Goals: every construct in the pinned v4 schema and the Union draft has a Python model and an expanded spelling; every new construct has an explicit downgrade failure; the reference model can reach v4 JSON through an explicit choice; nothing that works today stops working, except the typed Hole.reason.

Non-goals: compact spellings, legacy one-release spellings and the legacy_spelling warning (morphir-ukvn.8.16); the 4.1.0 linked annotations; removing the deprecated constructs; type checking of unions.

Decisions

INP-1. Per-input attributes drop only on request

Upstream v4 has no slot for them, and adding one is not a spelling to "find": the reference model, the kit and the reference implementation all agree that an input is a bare type. So no upstream proposal is needed. The Python side gets an explicit drop: drop_input_attributes(lib) for any v4 Library, a drop_input_attributes=True keyword on v3_to_v4, and ir convert --drop-input-attributes. An input loses information when its attributes are neither empty nor exactly ValueAttributes(inferred_type=declared); only those inputs report input_attributes_dropped. The drop walks let-bound definitions too.

Alternatives: drop always, as morphir-rust does. Rejected: it breaks the lossless in-memory round trip and the package's rule that loss is reported. Drop in the codec. Rejected: the codec has no warning channel and stays strict. Write the attributes into extensions. Rejected: an invented convention no other reader knows.

BODY-1. Four body classes, with the expression body keeping its name

value.Definition stays the expression body, with its (name, attributes, type) inputs, so existing code and the v3 migration keep working. New frozen classes NativeBody, ExternalBody and IncompleteBody hold (name, type) inputs as upstream does. ValueDefinitionBody is the union of the four; module.Definition.values, LetDefinition.definition and LetRecursion.definitions hold it, because the schema's let bindings reference ValueDefinition.

Alternative: one Definition with a body sum type, as morphir-rust does. Rejected: it changes the constructor of every existing definition.

HOLE-1. Typed hole reasons, shared by values and incompleteness

UnresolvedReference(target), DeletedDuringRefactor(tx_id) and TypeMismatch(expected, found) live in a new incompleteness module with HoleIncompleteness(reason, partial_body) and DraftIncompleteness(). Hole.reason becomes HoleReason. The schema gives the hole's partialBody the type Type, so HoleIncompleteness.partial_body is a type; an incomplete value keeps its partial expression on IncompleteBody.partial_body, as kit definitions-0025 shows. The reference model's Draft(notes) has no member in the schema; the pinned schema wins.

ANN-1. Annotations keep their spelling

CompactAnnotation(name, text) and StructuredAnnotation(name, arguments) mirror morphir-rust, because the kit writes an argument-less structured annotation as an object and a compact one as a string, so the form is content. The free text is everything after the first colon after #. Arguments are PositionalArgument(value) or NamedArgument(name, value); a named argument is an object with exactly name and value, anything else is a positional value. Specifications get an annotations field with an empty default, placed last so positional construction still works.

UNI-1. Union is a type node with two or more alternatives

type.Union(attributes, alternatives), spelled {"Union": {"attributes"?, "alternatives": [...]}}. Encode and decode refuse fewer than two alternatives with invalid_json at alternatives. Order, duplicates and nesting are kept. map_attributes handles it.

DEP-1. Deprecate, do not remove, the Python-only constructs

The Native and External value nodes and TypeConstraints stay, with docstrings that say they are deprecated and what replaces them. Removing them would break imports from morphir.ir; a follow-up bead removes them in a later minor release.

MIG-1. Every new construct fails downgrade with unsupported_v4_downgrade

Format 3.0.0 has no home for any of them. Constructs: NativeBody, ExternalBody, IncompleteBody, IncompleteTypeDefinition, Union, Annotations (on any specification). The pass still collects every failure.

Migration plan

One release of morphir. No data migration. Rollback is a revert of the PR.
