Context

See proposal.md, Why. The v4 reader already accepts every spelling the pinned schema allows. The writer builds each node in packages/morphir/src/morphir/ir/v4/codec.py with _wrap(tag, _with_attributes(attrs, members)), recursing through about 50 call sites that thread only a location. morphir-core 0.2.0 is the reference writer at the same profile: it chooses compact or expanded per node from a thread-local encoding and writes doc flattened and first.

Encoding the morphir-core output of the compiler fixtures with the current Python writer differs only in the node shapes listed in the proposal: type references, tuples, literals, variables and references.

Goals and non-goals

The default output of a model must equal morphir-core's output for the same model, byte for byte, including member order. Nothing in the decoded model may change. Not covered: field order in records or maps beyond what the model holds, number lexemes that Python's json does not keep, and the deferred re-sync items listed in the proposal.

Decisions

CDC-1. Select the spelling per public call with a context variable

A Spelling enum (COMPACT, EXPANDED) is held in a contextvars.ContextVar that defaults to COMPACT. Public encoders take a keyword-only spelling: Spelling | None = None. They set the variable for the duration of the call only when given one, so nested public encoders inherit the caller's choice. Each node encoder reads it once.

Alternative: a parameter on every internal encoder. Rejected because about 50 recursive call sites and the _keyed helpers would each have to forward it, and one missed forward would silently mix spellings. The context variable is task- and thread-local, matches morphir-core's design, and tests check both spellings over every node kind.

CDC-2. Compact only nodes without attributes

Each node first builds its expanded members as today, then returns the compact form when its attributes are empty. The table follows morphir-core's serialize_compact_type, serialize_value, serialize_pattern and serialize_literal.

CDC-3. Flatten documentation in both spellings

_encode_documented writes {"doc": text, **members} with doc first. Decision 0010 makes this the canonical form, and the nested wrapper is only a reader compatibility spelling, so the expanded spelling uses it as well. A documented node whose encoding is not an object, such as a compact string type, cannot occur at the documented positions: type and value definitions and specifications are always objects. The encoder fails with no_v4_spelling if it ever does.

CLI-1. Expose the choice in ir convert only

ir convert --to v4 gains --v4-spelling compact|expanded, default compact. compile --ir-version v4 writes the default compact spelling, which is also what the native compiler emits.

Risks and trade-offs

RiskMitigation
A downstream reader accepts only the expanded spelling--v4-spelling expanded and Spelling.EXPANDED; the proposal marks the change BREAKING.
Compact and expanded spellings mix in one documentA test walks the expanded output of every node kind and finds no compact form. The byte-for-byte fixture test covers the compact side.
Ambiguous stringsThe reader already separates FQName strings (containing : and #) from names, as the schema patterns do. Round-trip tests cover both.

Migration and rollback

This is a minor release of morphir and, for the CLI option, of morphir-python. Readers are unaffected. To roll back, select the expanded spelling or revert the change; no stored data needs migration, because both spellings decode to the same model.
