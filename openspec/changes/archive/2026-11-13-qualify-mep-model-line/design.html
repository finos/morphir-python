Context

See proposal.md, "Why". The model line is in model_transport.rs on morphir-extension-sdk 0.4.0. The SDK selects the intersection of the host offer and the guest support in the host's order, and the guest admits each call against the session tuples. These facts were true in extension/python/v0.5.0:

Item0.5.0
Protocol versions0.2.0-draft.1, 0.1
Claims version0.1.0-draft.2
Model tuplescompileModel and generateModel × morphir-ir / morphir-json / 0.1.0-draft.1 / IR 3.0.0 and 4.0.0
IonNot offered. Ion evidence is refused on WASM and native alike.

Goals and non-goals

  • Goal: tests that fail if negotiation, admission or the model outputs change.
  • Goal: evidence that the MoonBit worker host runs the model line from both CLIs.
  • Non-goal: Ion, dependencies in compileModel, or any change to finos/morphir-moonbit or finos/morphir.

Decisions

TST-1: golden files hold the exact payload bytes

The envelope golden file replaces payload.content with a placeholder, and a second file holds the decoded payload bytes as the guest wrote them. The SDK decodes the payload only after it checks length and SHA-256, so the payload file's digest equals the envelope digest. Pretty-printed IR 3 was 215 KB against 18 KB of exact bytes, and it would not catch a change in serialization. The files are -text in .gitattributes and excluded from the whitespace hooks.

Set MORPHIR_UPDATE_GOLDEN=1 to write them again after an intended change.

TST-2: run golden outputs through a negotiated session

Calling compile_model directly skips the SDK's session admission. The golden test sends JSON-RPC messages to a session that a host initialized with all four tuples, so it also covers selection, admission and serialization of the result.

QUAL-1: qualify without changing finos/morphir-moonbit

The host's Python suite pins 0.4.1 and 0.4.2 and checks MEP 0.1 only. A separate script outside both repositories drives the CLIs built from a clean main checkout with the same contract 0.2.0 WASM pin shape, the same environments (no Node on the native CLI's PATH) and the same checks as the host's Elm model-line suite. The receipt records the CLI program digests and the commit, which prove that the host is unchanged.

REL-1: release 0.6.0 as a minor version

The protocol surface is the same as in 0.5.0, but the compiler now builds with Ruff 0.0.20 and current dependencies. That can change parsing or generated text, so it is a new minor version, not a patch. The extension tag builds its native wheel from source in the same run, so it needs no native or CLI release.

Risks and trade-offs

  • [A Ruff update changes generated text] → the golden test fails and shows the difference; update the files only after review.
  • [The published CLI morphir-python 0.1.2 keeps compiler 0.5.0] → the documentation says which compiler each package pairs with; a native and CLI release is a separate decision.
  • [The MoonBit host offers model tuples for IR 4.0.0 only, and refuses --ir-version 3 for any guest that supports the model line (apps/morphir/cli/extension.mbt)] → the qualification records that refusal as an expected row; IR 3 model operations are covered by the Rust session and golden tests. With 0.4.2, which declares only MEP 0.1, the host compiled IR 3. This is a host change for finos/morphir-moonbit, tracked in its own bead.
  • [On the npm CLI a WASM worker runs on a Node worker thread] → its documented stop method is thread-termination; the qualification still requires an acknowledged shutdown and exit code 0. The process executable and the native CLI's WASM worker stop by themselves (exited-after-exit).

Migration plan

No migration. Hosts on MEP 0.1 keep working: the finos/morphir Rust host pins extension/python/v0.4.2, and the 0.1 suite repeats for 0.4.1 and 0.4.2. To roll back, hosts keep or restore their 0.5.0 pin; released bytes do not change.

Delivery close-out

PR #80 merged as 560a6503b8ffcab87ea667391579b747757bec0d. Manual release run 41267831018 passed without publishing, and release run 41300584158 published 0.6.0. Its WASM digest ce0cba07f0395ff8179b42eb021ade05c68197f69b8e9c0c8bc369d2a035727c matches the dry-run bytes documented as passing all 32 MoonBit model-line rows.
